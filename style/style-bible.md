# 스타일 바이블 — 한지 수채

> **D15 확정** (2026-09-13) · 스토리 `goldaxe` 이후 전 스토리 공통
> 이 파일이 바뀌면 **에셋 전량을 다시 뽑아야 한다.** 바꾸기 전에 그 비용을 계산할 것.

실제로 뽑아서 플레이어에 올려보고 확정한 방향이다. 추측이 아니라 화면에서 확인된 값이다.

---

## 1. 스타일 토큰

**모든 이미지 프롬프트 맨 앞에 통째로 붙인다.** 요약하거나 일부만 쓰면 그림체가 흔들린다.

```
Korean folk tale picture-book illustration, hanji paper watercolor with visible paper grain,
soft brush ink outlines, muted earth palette of sage green, clay ochre and warm grey,
flat even daylight with no harsh shadows, characters 2.5 heads tall with rounded
simplified forms and small gentle features, hand-painted children's book art,
no text, no lettering, no watermark, no signature
```

Flow처럼 영상이 기본인 도구에서는 아래 한 줄을 더한다.

```
completely static image, single still frame, no camera movement, no motion, no animation
```

## 3. 캐릭터 규격

| 항목 | 값 |
|---|---|
| 비율 | **2.5~3등신** |
| 얼굴 | 작고 단순한 이목구비, 점 같은 눈, 볼 홍조 |
| 손발 | 단순화, 손가락 구분 최소 |
| 외곽선 | 화면 높이 대비 약 0.3%의 균일한 붓선 |
| 명암 | 평면. 그림자 없음 |
| **방향** | **전부 오른쪽을 향해 한 벌만** 만든다 |

**방향 규칙.** 무대 연출의 기본은 인물이 무대 안쪽을 보는 것이다. 왼쪽에 선 인물이
왼쪽을 보면 화면 밖을 보는 꼴이라 어색하다. **오른쪽을 향해 한 벌만 만들고**,
오른쪽에 배치할 때 `story.json` 에서 `"flip": true` 로 뒤집는다. 에셋이 반으로 준다.

예외: 산신령은 항상 나무꾼의 오른쪽에 서므로 **왼쪽을 향해** 만든다.

### 레퍼런스

```
style/refs/woodcutter_sheet.png    나무꾼 — 정면/측면/얼굴
style/refs/spirit_sheet.png        산신령 — 정면/3/4/얼굴
```

**포즈를 뽑을 때마다 해당 시트를 레퍼런스로 첨부한다.** 이걸 빠뜨리면 컷마다 다른
사람이 되고, 그것이 AI 동화 앱이 실패하는 1순위 원인이다.

## 4. 배경 규격

| 항목 | 값 |
|---|---|
| 화면비 | **21:9** (16:9 화면의 1.3배 — 카메라 팬 여유) |
| 원근 | 얕게. 깊이 레이어 **3개 이하** |
| 지평선 | 화면 하단 1/3 |
| 명도 | **밝고 높은 톤.** 어둡고 무겁게 가지 않는다 |
| 디테일 | **최소.** 큰 단순 형태 위주 |
| 인물 | **없음** |
| 하단 중앙 | **비워둔다** — 캐릭터가 설 자리 |

> **배경은 물러나 있어야 한다.** 배경 정보량이 캐릭터보다 많으면 분리가 연출이 아니라
> "캐릭터를 덜 그렸네" 로 읽힌다. 렌더 단계에서 `blurPx: 1.0` 을 더 얹는다
> ([Spec §5.7](../StoryTellingSpec.md#57-배경-후처리--배경을-한-발-물린다)).

Flow가 21:9를 못 내면 16:9로 받고, 그 배경을 쓰는 비트는 `camera` 를
`panLeft`/`panRight` 대신 `still` 이나 `pushIn` 으로 둔다.

## 5. 배경 처리 — 오려내기 vs 더하기

| 종류 | 배경 | 이유 |
|---|---|---|
| 캐릭터 · 소품 · 선택지 그림 | **마젠타 `#FF00FF`** | 불투명체. 크로마키로 오려낸다 |
| **발광체** (빛·불·안개·반짝임) | **순수 검정 `#000000`** | **반투명이라 오려낼 수 없다.** `screen` 으로 더한다 |
| 배경 | 그대로 | 오려내지 않는다 |

마젠타를 쓰는 이유: 살색·초록·하늘색과 색상 거리가 가장 멀어 오탐이 적다.

**분홍의 진하기는 상관없다.** 플레이어가 모서리에서 배경색을 직접 읽어 기준을 맞춘다.
분홍 정도를 `K = (R+B)/2 - G` 로 재는데, 배경과 피사체가 확실히 갈린다.

| 색 | K |
|---|---|
| 진한 마젠타 `#FF00FF` | 255 |
| 자주 `#C71585` | 77 |
| 연분홍 `#FFB6E1` | 58 |
| 볼 홍조 (피사체) | 15 |
| 살구 피부 (피사체) | 1 |
| 미색 의복 (피사체) | -3 |

배경의 K가 **22 미만**이면 분홍으로 보지 않고 그대로 둔다 (플레이어가 알려준다).
거의 흰색에 가까운 아주 옅은 분홍만 여기 걸린다.
검정이 회색빛이면 화면 전체가 뿌옇게 들뜬다 — `pure #000000 black, absolute black, no grey`.

## 5.5 여러 개를 한 장에 뽑아도 된다 `지금은 쓰지 않음`

> 현재 작업판은 **한 장에 하나씩** 뽑는 방식이다. 아래는 나중에 쓸 수 있는 선택지로
> 남겨둔 것이며, 플레이어는 이미 지원한다.

같은 성격의 소품·아이콘은 **한 장에 나란히** 뽑는 편이 낫다. 한 화면에서 서로 비교되며
생성되므로 크기와 그림체가 저절로 맞는다. 플레이어가 덩어리별로 잘라 준다.

**조건 두 가지**

1. **서로 닿으면 안 된다.** 닿으면 한 덩어리로 인식된다.
   프롬프트에 `evenly spaced with clear wide gaps, NOT touching each other` 를 넣는다.
2. **왼쪽부터 순서를 지정한다.** 플레이어가 왼쪽부터 1·2·3번으로 정렬해 보여준다.
   `From left to right: 1) … 2) … 3) …` 형식으로 쓴다.

부스러기(반짝이 등)는 자동으로 버려진다 — 가장 큰 덩어리의 12% 미만이면 무시한다.

**묶지 말아야 할 것**: 캐릭터 포즈(각자 전체 해상도가 필요하고 시트를 물려야 한다),
배경(21:9 한 장이 곧 한 화면이다).

## 6. 금지

- **디즈니풍 / 3D 렌더 / 애니메 스타일** — IP 리스크 + 차별화 실패
- 원색, 높은 채도
- 강한 그림자, 드라마틱한 조명
- 세필 디테일 (배경이 캐릭터를 잡아먹는다)
- 글자·서명·워터마크
- 캐릭터 발밑 그림자·바닥선 (컷아웃 후 회색 얼룩이 남는다)

이 문서를 고치는 순간 **모든 에셋이 구식이 된다.** 수작업 환경에서는 잃어버린 하루다.

- 정말 스타일 문제인가, 아니면 [배경 후처리](../StoryTellingSpec.md#57-배경-후처리--배경을-한-발-물린다)로 해결되는가?

- 아이가 실제로 싫어했는가, 어른 눈에만 아쉬운가?
